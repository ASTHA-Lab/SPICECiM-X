SPICECiM-X — Help & Tutorial

SPICE-accurate simulation of Vision Transformer inference on ReRAM (1T1R) analog in-memory-computing crossbars.

SPICECiM-X maps every static-weight matmul of a trained ViT onto differential 1T1R crossbars. That covers Q/K/V, W_O, FFN W1/W2 and the head. It simulates the crossbars with Cadence Spectre, with the jobs dispatched in parallel across your licenses, or from SPICE-built tables in fastdc. An affine de-map and a voltage pre-warp recover floating-point results. Softmax, LayerNorm and the activation × activation products run digitally. It reports accuracy (SW–HW agreement and, with labels, against ground truth), energy, latency and TOPS/W.

How to use this page Use the left index to jump between sections. The search box at the top filters the parameter tables in the Configuration Reference. All commands run from the repository root, and the annotated reference configuration is config_cifar10.ini.

1Features & Capabilities

Five simulation modes

transient, dc, fastdc, hybrid, and auto, which runs a transient energy pass followed by a fastdc accuracy pass.

Full analog chain

1T1R cell, BL driver, differential ±TIAs, subtractor and ADC. Each converter can be an analytic model (S) or a SPICE-characterised subckt (H), in every mode.

Config-driven PDK

Transistor geometry and Verilog-A device params live in [PDK]. The transient and DC decks both use them, together with [HW] and [PARASITICS].

Operating-point aware

Process corner, Vdd/Vss, temperature and tnom drive both inference and the characterisation that calibrates it.

Cached characterisation

The array table is built once and cached by a hash of the hardware config. It rebuilds automatically when that config changes, and a failed Spectre run aborts the build instead of caching a bad table.

Parasitics

Per-cell wire R/C reproduces IR drop, and the characterisation tracks it.

Energy & latency models

Walden / Accelergy ADC, switched-cap DAC, static-bias TIA, cycle-accurate latency, bit-slicing, converter sharing, node and corner scaling.

Accuracy reporting

Torch-vs-GT, IMC-vs-GT and SW–HW agreement with top-k, via an extensible task registry.

Desktop GUI

A config editor and run console with one tab per section, Run / Stop / Save / Report, S | H peripheral switches, and this help page.

Install

From the repository root. The package directory is SPICECIMX_V3, and the name is case-sensitive:

pip install -e "SPICECIMX_V3[torch,test]"

# sanity check of the IMC kernel (numpy only, no Spectre)
python -m spicecimx.cli.run --selftest
GUI on Linux If the GUI raises ModuleNotFoundError: No module named 'tkinter', install your distribution's Tk package, for example sudo apt install python3-tk.

Quick Start

  1. Point the config at your PDK and images. No PDK data ships with SPICECiM-X. In config_cifar10.ini, replace the /path/to/… placeholder in [PATHS] transistor_model with your PDK .scs, set stdcell_netlist to a std-cell netlist for your PDK (start from supports/standard_cell.netlist and keep its subckt names and pins), set [PDK] transistor_model_name, and point images_dir at a folder of test images. Relative paths resolve against project_dir, which resolves against the config file's folder. See supports/README.md.
  2. Train or bring a checkpoint. python main.py --config config_cifar10.ini writes best.pt/last.pt to [SAVE] out_dir.
  3. Characterise once. python -m spicecimx.cli.characterize --config config_cifar10.ini (cell table, for fastdc/auto) and python -m spicecimx.cli.characterize_array --config config_cifar10.ini (array table). infer also builds the array table automatically if it is missing or stale.
  4. Run. python -m spicecimx.cli.infer --config config_cifar10.ini --images_dir Test_Image/t1_ds --limit 100. You can also open the GUI with --gui and press Run.
  5. Read the reports under <dump_root>/<batch>/, where <batch> is the folder name of images_dir.
First run is the slow one The array characterisation is a one-time Spectre sweep, cached at [PATHS] array_table_path. Later runs with the same hardware config reuse it.

The Pipeline

StageCommandProduces
0. Trainingpython main.py --config … best.pt / last.pt in [SAVE] out_dir.
1. Cell characterisation fastdc cli.characterize Single-cell I–V table for fastdc, and the dc fallback pre-warp, written to [PATHS] char_table_path (.npz).
2. Array characterisation cli.characterize_array (also auto-invoked by inference) Subarray I–V table at two sizes. It is used for the voltage pre-warp in every mode and for R_access = auto.
3. Inference cli.infer Predictions, accuracy report, and per-inference power/energy/latency report.
When the table rebuilds The array table hash covers the transistor model, corner, vdd/vss, temperature, tnom, the [HW] device params, [PDK], [PARASITICS], the grid, the DC Verilog-A and the std-cell netlist. R_access is not included because it is derived from the table. Use characterize_array --force to rebuild deliberately.

4Runtime Commands & GUI

Launch the GUI

python -m spicecimx.cli.infer --config config_cifar10.ini --gui
python -m spicecimx.cli.gui --config config_cifar10.ini

The GUI has one tab per config section. The toolbar:

  • Run / Stop: saves the config, launches spicecimx.cli.infer with the config's folder as the working directory, and streams the log. Stop terminates the run.
  • Save config: writes your edits back to the .ini.
  • Report: shows Final_report.txt, the accuracy summary and the energy report of the current batch.
  • Help / Tutorial: opens this page. Clear log clears the console. extra CLI args appends flags, for example --mode auto --limit 5.

Inference

python -m spicecimx.cli.infer --config config_cifar10.ini [options]
FlagMeaning
--config PATHConfig file. The default is config.ini, so pass it explicitly.
--mode MOverride [SIM] mode: transient / dc / hybrid / fastdc / auto.
--images_dir DIROverride the image folder. Its leaf name is the batch id.
--checkpoint PATHExplicit checkpoint. A path that does not exist is an error.

--licenses NOverride license_count.

Command-line paths are relative to the current directory. Without --checkpoint, the run looks for <out_dir>/best.pt, <out_dir>/last.pt, then <project_dir>/outputs/{best,last}.pt. It never picks the newest *.pt elsewhere. The state dict is loaded strictly, with the module. and _orig_mod. prefixes stripped. The input channel count is read from the checkpoint.

Characterisation commands

# array table (normally automatic; --force rebuilds)
python -m spicecimx.cli.characterize_array --config config_cifar10.ini [--force]

# single-cell fastdc table; DC Verilog-A defaults to [PATHS] device_model_dc
python -m spicecimx.cli.characterize --config config_cifar10.ini [--output supports/cell_table_45nm.npz]
    [--veriloga FILE] [--corner tt] [--work_dir DIR] [--spectre BIN]
    [--T_min --T_max --T_step --V_min --V_max --V_step]
Cell table format characterize writes an .npz that stores its own grid; the reference config's char_table_path (supports/cell_table_45nm.npz) is where it lands by default. A .csv table exported from ADE also works, but it has no V axis, so fastdc_V_min/V_max/V_step must match its column count (e.g. 0..1.0 V in 0.01 V steps = 101 columns).

[INTERCONNECT]

What the RSN decomposition leaves out: the lines that join a layer's subarrays (loading) and the network-on-chip that joins the tiles. With loading, transient runs every layer as a loaded RSN: pass 1 is the ideal RSN, a line solve predicts the boundary, and pass 2 re-runs every deck with each column ending in its Thévenin equivalent of the shared line. A third pass runs if the residual exceeds the tolerance. fastdc applies the same line solve. Validate with python -m spicecimx.cli.check_loading. The outputs go to interconnect_report.json and the Tile lines / NoC rows of the energy report.

Crossbar energy comes from SPICE only in transient mode, including the transient pass of auto. The other modes report peripheral energy and latency only.

auto mode image selection

The transient image is chosen by auto_transient_image (a file name), then auto_transient_image_index (≥ 0), then auto_transient_num_images random images seeded by auto_transient_seed. With N > 1 images, the crossbar energy is averaged, and each image's data is kept under timgXX_<name>/.

Peripherals: S | H

An S converter uses the analytic TIA/ADC model and the [PERIPHERALS] energy model. An H converter is characterised once with Spectre at the start of the run, and then its measured transfer and energy are used in every mode:

  • DAC: a code sweep. The measured code → voltage table drives the crossbar inputs, with full scale [HW] vmin..vmax.
  • TIA → SUBTRACTOR → ADC: one chained sweep over ±adc_i_fullscale. A per-layer programmable TIA gain maps each layer's calibrated range onto that sweep, and the ADC codes become the output.

The measured energies (measured_converter_energy.json) replace the modelled ones in the energy report. If an H characterisation fails, the run stops; it never falls back silently to S.

Ready-made library

supports/peripherals/peripherals_8b.scs defines DAC_8b, TIA_8b, SUBTRACTOR_8b and ADC_8b. They are behavioural, power-annotated Verilog-A cores from the EnPower project, sized for 45 nm / 1.1 V, [HW] vmax = 0.6 V and adc_i_fullscale = 8e-4. Retune their parameters if you change those values.

[PATHS]
peripheral_netlist = ./supports/peripherals/peripherals_8b.scs
[SUBCIRCUITS]
dac = DAC_8b, H
tia = TIA_8b, H
subtractor = SUBTRACTOR_8b, H
adc = ADC_8b, H
Rules Any subckt with the same pins drops in unchanged: DAC INP<7:0>/OUT; TIA IN/OUT; subtractor INP/INN/OUT; ADC IN/CLK/OUT<7:0>; all also have VDD/VSS. tia/subtractor = H take effect only with adc = H. With adc = H the chain uses the tia and subtractor subckts named in [SUBCIRCUITS], even when those roles are S. multiplexer = H is not simulated. The cell and bl_driver rows are informational. infer prints a NOTE for each setting that has no effect.

C · Change the PDK / technology node

  1. Point [PATHS] transistor_model at the new PDK .scs and stdcell_netlist at matching std cells. Set [SIM] process_corner, vdd and vss.
  2. In [PDK], update the transistor geometry, transistor_model_name, wl_read_V and cell_prefix.
  3. Adjust [HW] vmin/vmax, the [PERIPHERALS] TIA/ADC windows and supplies, and [PARASITICS] for the node.
  4. Run inference. The array-table hash changes, so the table rebuilds at the new process. DC and transient both use the new [PDK] values.

D · Change the ReRAM device model

Update [PATHS] device_model_transient / device_model_dc and the [PDK] va_cell_* names, then the physics in [HW] (Tox/Tref/Ik1/Vref/Tmax/Tmin) and the dynamics in [PDK] va_*. The DC Verilog-A file is part of the array-table hash. A custom transient model should accept an enable_switching parameter, as supports/reram_cell.v does.

[SIM] process_corner = ss
[SIM] temperature = 85.0

The corner, vdd/vss, temperature and tnom are all hashed, so the array table rebuilds at the new point before inference runs.

[SIM] mode must be … on load Valid modes: transient / dc / fastdc / hybrid / auto. They are case-insensitive in the config.

Debugging workflow

  • Shrink the problem: cli.run --selftest checks the kernel without Spectre, and --limit 1 runs one image.
  • Start in fastdc to separate model and config issues from Spectre issues, then move to dc/transient.
  • Keep intermediates (omit --no_intermediates) and inspect the per-image CSVs under <dump_root>/<batch>/.
  • Keep va_enable_switching = 0 for inference. With 1, cells drift during long reads.
  • After a hardware change, look for cache STALE … rebuilding, or force it with characterize_array --force.

7Extending & Modifying

Add a new accuracy task

Subclass spicecimx.core.metrics.Task, which needs predict() and is_correct(). Register it before inference runs, then set [ACCURACY] task to its name:

# run_with_task.py
import numpy as np
from spicecimx.core.metrics import Task, register_task
from spicecimx.cli import infer

class MyTask(Task):
    name = "my_task"
    def predict(self, output):
        return np.argmax(np.asarray(output), axis=-1)
    def is_correct(self, output, gt):
        return np.asarray(self.predict(output) == np.asarray(gt)).ravel()

register_task("my_task", MyTask)
infer.main(["--config", "config_cifar10.ini"])

Swap the standard-cell or peripheral library

Point [PATHS] stdcell_netlist / peripheral_netlist at the new netlists and name their subckts in [SUBCIRCUITS]. Pin lists and bit widths are parsed from the netlists.

Tune the energy models

Each [PERIPHERALS] energy knob takes a measured pJ/op when > 0, otherwise a physical model. For SPICE-measured converter energy, use H converters.

FAQ & Tips

Do I need Spectre?

Yes, for every mode and for characterisation. fastdc inference itself only reads tables, but Spectre builds those tables once. cli.run --selftest and pytest run without it.

What is the difference between vmax, vmax_tia and vmax_adc?

[HW] vmax is the crossbar drive range. vmin_tia/vmax_tia is the TIA output window that each layer's calibrated current range maps onto. vmax_adc is the ADC full-scale voltage.

Why is the first run slow?

It builds the array table once. Later runs with the same hardware config reuse it.

Can I keep a previous run's files?

Set [SAVE] clean_workspace = false, or use a different images_dir leaf name: cleaning only touches the current batch.

How is the differential readout modelled?

[PERIPHERALS] differential_columns = true: a +column and a −column TIA feed a subtractor, then the ADC. With differential currents the affine de-map needs only the J·B offset term, because the baseline terms cancel.
